# 路线图

按"性价比从高到低"排，不是为了凑功能，每条都对应一个真实痛点。

## 已完成

- Word 文档 → 题库数据，一条命令搞定，自动认章节、自动识别题型
- 四种模式：测验 / 背题 / 错题本 / 模拟考试
- 答题卡、进度与收藏本地保存、题号缺口报警
- 题库与界面分离，零依赖、离线可用、双击即用

## 接下来值得做

### 1. 把"导入报告"做完整

现在只会报题号缺口。再加上：

- 哪几题没解析出答案
- 哪几题的选项数异常（比如单选只有 2 个选项）
- 疑似重复题（题干去空格后算指纹比对）
- 输出一份 `import-report.txt`，改题时对着看

这是所有做题库的人都吃过亏的地方，也是这个项目最容易做出差异的一点。

### 2. 试卷导出

模拟考交卷后，把整卷导出成适合打印的 HTML（A4 排版、题干选项、答案另附一页）。
浏览器自带的"打印 → 另存为 PDF"就能用，不需要后端。

### 3. 错题复习排期

现在错题只是"答对就移出"。更合理的是按记忆曲线安排复习时间：

- 参考 Anki 的 SM-2 或 FSRS 算法，给每道错题记一个"下次该复习的日期"
- 首页给一个"今天该复习的 12 题"
- 这块属于纯算法，很适合拿来练手，而且做完自己真的受益

### 4. 标签体系

给题目加知识点 / 难度标签（可以写在 Word 里，也可以单独放一个 `tags.json`），然后：

- 按标签筛选、按标签组卷
- 统计"哪几个知识点我错得最多"

### 5. 导入格式扩展

- Excel / CSV 导入（`openpyxl` / `pandas`），方便不写 Word 直接填表
- 从 PDF 提取（`pdfplumber`）——只有手上确实是 PDF 时才值得做

### 6. 手机端体验

- 加 PWA 的 manifest 和 service worker，手机浏览器"添加到主屏幕"，离线也能用
- 配合 GitHub Pages，等于免费拥有一个自己的刷题站点

### 7. 工程化升级

等前面几条稳定了再考虑，不要一开始就上：

- 用 Vite + Vue 3 + TypeScript 重构界面（现在 900 行的 `assets/app.js` 会拆成组件）
- 给组卷、判分、导入解析写单元测试
- 加 GitHub Actions 做构建校验

## 明确不做

- 不做多用户账号、不做后端服务。真需要"多人协作管理题库"时再单独开一个项目
- 不做付费解锁。纯前端挡不住任何人，要做就得有服务端，那是另一个量级的工程
- 不把别人的题库内容打包进来。仓库只放系统、数据格式和示例题
